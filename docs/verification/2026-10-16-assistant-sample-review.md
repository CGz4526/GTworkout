## Web 响应修复

修复前的独立镜像检查复现了两个问题：`/assets/` 下缺失的 JS/CSS 经 SPA 回退返回 200 HTML；首页、SPA 深链和 manifest 没有明确缓存策略。缺失资源返回 HTML 会掩盖资源错误，且无法作为 JavaScript 执行。

`infra/nginx/default.conf` 现将带构建哈希的 assets 限为真实文件，缺失返回 404；成功资源设置一年 immutable。index.html、manifest 与已有 sw.js 使用 no-cache，让客户端复核新版本；正常 SPA 深链继续回退首页。no-cache 允许保存但要求重新验证，不等于禁止缓存，也不能代替 PWA 更新验收。

隔离检查 `infra/check-web.ps1` 仅运行本机已有镜像，通过镜像 ID 创建无网络、无宿主端口、无卷的临时 Nginx，完成检查后按唯一标签回收本次容器。它不连接当前 Java、数据库或用户浏览器。

```powershell
.\infra\check-web.ps1
```

实际验证：修复前检查失败，修复后 10/10 通过，包括首页与 history/cloud 深链、sw.js、manifest、现有 JS 缓存、缺失 JS/CSS 404、健康检查和 Actuator 屏蔽。Nginx 配置语法检查通过；前端 lint 通过，Docker 构建成功并更新 web，server/db 容器 ID 保持不变。后端业务代码未改，未重复运行上一批已通过的 100 项 verify。

证据位于 `.cache/web-check-<UUID>.json`；基线失败记录保留。容器响应检查不是浏览器性能、离线或移动端测试，前端主包体积警告仍在。
