### 任务与事务演练

- 三个竞争领取者只能取得两个不同任务，第三个得到空结果。
- 独立连接锁住一个任务行时，另一个领取在 2 秒测试期限内跳过被锁行并取得其他任务，实际验证 SKIP LOCKED。
- 续期不能超过单次执行总期限；旧执行代号不能续期或提交。
- 插入部分投影后注入故障：投影记录回滚，任务不会显示成功。
- 发布期间由独立提交的连接使租约过期：最终条件更新失败，先前插入的投影全部回滚；新代号成功恢复且没有重复投影。
- 三次租约过期后停止自动尝试，任务与备份同事务标记失败；原文件仍可下载。
- 人工重试最多三次，达到上限明确拒绝；READY 不重复投影。
- P1 风格 NOT_REQUESTED 备份不被自动领取；显式申请才创建任务。
- 空快照可完成处理，统计为零且覆盖范围为空，不用假日期填充。
- 两用户无法访问对方统计或任务；原上传、下载、会话、幂等和额度测试保留。

### 真实进程中断

P2ProcessRecoveryIT 创建自己的一次性 PostgreSQL，启动独立测试 JAR 进程。通过测试连接暂时阻止投影写入，等任务实际变为 RUNNING 后强杀该测试进程，确认不存在半份投影；随后启动另一测试进程，等待真实 30 秒租约到期和有限退避，验证第二次尝试 SUCCEEDED、备份 READY、原字节一致、统计容量 770。

这不是只改数据库状态模拟重启，也没有强杀当前用户的应用进程。测试还通过真实 HTTP 验证 ISO 日期筛选、缺少结束日期被拒绝、训练分页、动作列表和动作趋势（夹具中的深蹲容量 720）。测试的数据库、端口和进程与运行中的 workout 项目隔离，结束后由测试生命周期回收。

## 发现的问题与处理

1. PostgreSQL 覆盖日期查询最初使用保留字 day 作别名，真实 SQL 测试失败；改为明确别名并复验。
2. 复核发现旧心跳可能在任务已结束、线程复用后迟到返回；通过生命周期锁确保旧心跳不能中断新任务。
3. 复核调整发布锁顺序：先完成任务代号条件更新，再更新 READY，同事务提交；避免与终态恢复的 job→backup 锁顺序相反。
4. 日期查询参数显式指定 ISO.DATE，并补真实 HTTP 断言；空快照 coverage 为空的情况显式处理。

没有关闭测试、忽略错误或增加假成功返回。只有暂时/可恢复数据访问及连接故障自动重试；校验、约束、语法与程序错误不盲目重试。
