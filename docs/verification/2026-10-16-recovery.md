## 一致性与隔离方法

- 源连接开启 REPEATABLE READ READ ONLY 并导出快照，pg_dump 和源数据摘要导入同一快照，避免在线登录/任务更新导致比较时刻不同。快照持有上限 10 分钟，超过后演练失败，不输出假成功。
- 每张公共表按列顺序生成 JSON 行表示，BYTEA 先计算 SHA-256，避免将完整照片/备份拼入 JSON；每行再计算 SHA-256。按表名和摘要排序输出清单，最后比较清单 SHA-256。清单不保存用户名、Cookie 或原文件内容。
- 全新容器使用相同镜像、network=none、无端口、1 GiB tmpfs 数据目录、256 MiB 内存限制。仅容器内部初始化使用 trust，不修改源数据库认证或任何凭据。
- pg_restore 使用 exit-on-error，恢复到新库，不使用 clean/drop。SQL 错误不回显可能含原始行内容的诊断。
- finally 根据本次唯一标签验证归属，只回收本次临时容器。归档保留在宿主机；源库只运行查询/导出，不更新数据。

## 适用范围

这是小数据量、同机 PostgreSQL 逻辑恢复演练；临时数据上限 1 GiB，数据更大需另行规划容量。未启动恢复库对应的 Java 服务，因此尚未验证恢复后登录、HTTP 下载、RUNNING 任务恢复和完整应用就绪链路；会话行保存不等于 Cookie 必然仍有效。

没有验证异地副本、定时备份、加密归档、宿主机损坏、历史版本回退，也没有承诺 RPO/RTO。原浏览器 IndexedDB 不属于后端数据库归档范围，仍需保留已有 JSON 导出。
