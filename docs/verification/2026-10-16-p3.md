### PostgreSQL、HTTP 与规则边界

- 真 HTTP 登录、CSRF、匿名拒绝、创建任务 202、读取结果、版本确认；服务层另验其他用户读取任务/动作库/草案/确认均拒绝。
- 同 key 并发创建取得同任务，只有一个 created=true；同 key 不同请求 409；用户已有活跃任务时不能再创建。
- 完整动作库包含从未练过的动作，而历史动作列表不包含它；描述字段未发送给模型。
- READY 前、无模型配置时不创建付费任务。
- 原子领取不重复；过期 RUNNING 终止为 MODEL_OUTCOME_UNKNOWN，不重新入队；旧代号不能发布草案。
- 草案插入失败时，先前任务成功更新同事务回滚；不会出现 SUCCEEDED 却缺草案。
- 模型故障只调用一次，FAILED 无草案，不自动重试；模型没有写库工具。
- 规则检查允许动作、天数、组数/次数、间歇、重复动作、估算时长与额外字段；无效计划最多修复一次。
- 本机假 HTTP 服务验证 DeepSeek 请求格式、首次强制比较工具、后续 JSON、限额、HTTP 302 不跟随、401/429/500 不重试、响应超限取消及大上下文拒绝；这些不消耗真实模型预算。

## 真实模型联调

用户明确允许本次使用所给密钥，最多 10 次请求，并指定 deepseek-v4-flash。凭据通过无回显输入传给独立 Java 演练进程，仅存在内存；演练连接自己的 Testcontainers PostgreSQL。最终本机 server 通过进程环境注入凭据，不写源码、镜像或 .env。

[DeepSeek 官方文档](https://api-docs.deepseek.com/quick_start/pricing/)说明旧标识 deepseek-v4-flash 当前由 V4.1 Flash 提供服务。本报告记录请求标识，不把它当成冻结权重版本。

| 实际任务 | 请求数 | 工具数 | 服务商 reported tokens | 最终状态 |
|---|---:|---:|---:|---|
| 首次 3 天/60 分钟：发现跳过工具 | 2 | 0 | 1,590 | FAILED，未保存草案 |
| 修复后 3 天/60 分钟 | 4 | 4 | 4,500 | SUCCEEDED，3 天估算各 12 分钟 |
| 修复后 1 天/15 分钟 | 4 | 4 | 4,440 | SUCCEEDED，估算 11 分钟 |

累计 **10/10 次真实请求**，包含失败请求，未再调用。成功案例还验证草案确认与重复确认结果相同。reported tokens 合计 10,530；这不是实际账单金额，也不能推导生产费用。

成功案例观测模型任务耗时约 3.54 秒与 2.98 秒，仅本次小型合成数据，不是延迟承诺或训练建议质量评价。两次成功不足以计算稳定的 Agent 成功率。

P3LiveProbe 不在默认 verify 自动运行；后续执行前先检查现有预算。累计预算保存在忽略目录的 p3-live-budget.txt，带文件锁、每次调用前持久化，当前已到上限，禁止擅自重置以继续调用。

## 发现与修复

1. Jackson 3 默认完整文档尾随校验不适用于逐个动作子树读取，导致动作库读取错误。为仅用于已验证备份的流式子树 mapper 明确配置读取方式，新增双动作/跳过照片测试；原始备份入口的重复 key、尾随内容等校验保持严格。
2. 初始工具 auto 配合已有依据统计，让模型直接给出计划。服务端按“须查询工具”规则拒绝，修复为首轮强制 compareTrainingPeriods、随后输出 JSON，补 HTTP 协议回归并完成真实复验。
3. 前端轮询依赖从整个 run 对象改为稳定任务 ID/活跃状态，避免每次更新触发立即重复轮询。
4. 新本地测试依赖触发 npm Windows 可选依赖锁树缺失，Linux npm ci 拒绝构建。用与 Dockerfile 相同的固定 Node 镜像，在独立缓存目录补全已有锁文件的可选依赖树；未绕过 npm ci，未升级全局工具，随后严格构建通过。
