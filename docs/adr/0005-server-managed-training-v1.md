# ADR 0005：服务端训练首版与独立账号缓存

日期：2026-10-17。状态：首版实现，当前运行环境切换待授权。

## 决策

后端管理账号正式训练。单次训练作为聚合提交，服务端事务保存训练、动作记录、组明细和幂等响应。用户行锁约束单用户首版并发，expectedVersion防止旧请求覆盖；设备ID仅作编辑流程约束，不能代替用户鉴权。

保留旧WorkoutDB，新增每账号独立WorkoutAccount-UUID数据库，保存训练缓存、动作缓存、冻结outbox与元数据，当前账号库schema从1开始。没有在旧库增加表或修改迁移。页面和原补录页通过仓储参数复用；账号训练使用新路由，访客入口不被自动切换。

后端新增五表通过审阅SQL显式在隔离测试库加载，没有新增自动Flyway迁移。training-write-enabled默认false；当前8088服务不被此次开发升级。

## 数据与同步取舍

- live_session.document保存同次输入的完整规范化训练文档，用于详情响应；关系字段/子表保存查询明细，二者在同一事务更新。不能从两条独立写链路更新，后续统计以关系列为准并做一致性测试。
- 聚合替换先验证所有子ID归属，再在同一事务替换本训练子行，保持用户提交的稳定ID和顺序；失败回滚包含幂等结果。只作用新业务表，不删除原备份/快照。
- 请求摘要为原始UTF-8字节，路径/操作类型/资源ID另在幂等重放时核对。冻结正文不重新序列化，避免请求未知结果时错误创建新意图。
- 本地保留最新草稿与一条冻结在途请求；旧响应仅推进serverVersion，不覆盖更新的草稿。账号切换停止旧队列，X-Expected-User防止Cookie变更后的误归属。
- 手机后台运行不可靠，因此只承诺应用前台/重新打开后有界重试；不会承诺关掉应用仍上传。重试耗尽保留记录并提供人工重试。
- 同设备多标签使用持久编辑租约；接管后保留owner围栏，旧标签不能因为新租约释放就提交旧内容。重新进入才重新读取草稿。服务端版本仍是最终写入约束。
- 列表排除取消项，客户端对历史中缓存过的已同步ACTIVE记录补查详情，将CANCELLED传播到本地，避免活动记录残留。

## 旧数据导入：缩小状态模型

首版不新增training_import/source_mapping表。导入来源限已有不可变云备份；用户必须先上传JSON或选择自己的备份，再预览并确认。日期按该备份已记录的时区解释。

旧实体ID使用固定版本算法UUID.nameUUIDFromBytes(workout-import-v1/user/type/legacyId)映射；组/训练动作使用不可变源文件中的稳定位置。mutationId再绑定文件摘要/时区，导入设备ID确定生成；同一输入可跨设备重建相同身份。原始备份及版本化算法构成可重建映射的持久依据，不能随意改算法或删除来源。

重复相同训练跳过；同旧ID不同内容/日期进入冲突，不覆盖。每条训练独立事务，失败统计与已成功数量分开，重试可继续；导入动作可能先于训练成功而保留。首版不是全文件原子迁移，不自动合并不同来源的相似记录。

限制为1000条源训练/批，只导入已完成训练及其动作；不支持字段和未完成记录在预览中计数。精度/类型不符不能静默截断，须报告非法记录并阻止确认。模板库、体重和照片不随此导入接管。

## 验证与后续

本决定取代R1中的单库复合账号索引方案及单独导入映射表设想；保留上层数据隔离与可恢复要求。全量同步、主动接管、历史改删、实时统计和Agent新来源属R4；生产切换属R5。验证证据见 [验收记录](../verification/2026-10-17-training-v1.md)。
