# 0003 持久任务与只读训练投影

2026-10-16。P1 基线复验通过后按既定 P2 方案实施。数据库迁移沿用用户“不影响现有数据即可执行”的授权；V3 新增派生结构、扩展 CHECK，不改 V1/V2、不更新旧备份字节，也不自动为旧备份创建任务。

任务与上传同库事务创建。轮询领取使用 SKIP LOCKED，计算在事务外进行，最终按批写入一份事务内投影。租约和执行代号共同约束提交；数据库 clock_timestamp 提供期限依据。投影数据、READY、任务成功同事务，事务失败不留下可见的半份数据。

领取许可覆盖排队与运行，总数 2；执行器并发 2、缓冲 2，不会无限预取。默认租约 30 秒、5 秒续期、单次最大 120 秒。旧执行者不能提交，迟到心跳不能干扰线程复用。SQL 单条语句设置 10 秒超时，连接建立/获取也有界。它提供至少一次执行与有条件结果发布，不声称外部调用恰好一次或多实例高可用。

发布阶段先写投影，再以任务 token/租约条件完成任务，最后更新 READY，全部同事务。失败/恢复采用相同 job→backup 锁顺序。续期在其他连接执行，不在等待数据库和大计算时长期持有任务行锁。

会话按原 ISO 与备份时区映射日期；保留源 ID、ISO、顺序和历史名称。缺动作定义保留组与容量，部位未知；不把照片复制到投影。独立 weights 优先，旧 session.weight 先按日期内最后时刻回填，再被独立记录覆盖。查询只访问 READY 的投影。

训练次数/训练天数/部位天数分开返回；热身和未完成组不计有效组；未完成训练不计统计。发现原 Stats 页的部位“天数”实际上按 session 累加，本轮不修改旧页面，云端按契约以日期去重并向用户说明。共享夹具在实际 TS 函数、Java 投影与 PostgreSQL 查询中核对。

新上传由 201 演进为 202，重放仍 200，响应新增 jobId；原字节下载不依赖投影状态。NOT_REQUESTED 与 FAILED 支持显式请求/有限重试，READY 保持不可变。按业务状态展示步骤，不添加虚构百分比。Agent 仍关闭。
