# 0004：有界 DeepSeek 教练任务与确定性草案

日期：2026-10-16。状态：采用。

## 决策

沿用原 P3 场景，以单次异步任务完成复盘依据查询和计划草案生成，不引入长期对话记忆或 RAG。Java 17 HttpClient 适配 DeepSeek 官方 Chat Completions，明确控制网络超时、响应大小、调用次数和不跟随重定向；不为单一协议接入增加框架依赖，也不声称已使用 Spring AI。

模型工具闭包绑定服务端用户/READY 快照，首轮强制 compareTrainingPeriods，再允许其他只读工具。最终输出只有固定计划结构；展示数字来自服务端统计，避免将模型自由文本当成统计事实。动作名称是不可信数据，允许动作集合及各项数值由确定性代码复核。

完整动作库按需从经过鉴权的不可变原文件流式读取，只保留 ID/名称/部位（名称和部位截断至 120 字符），跳过照片和备注。已有 P2 投影只保存历史动作，不能承担完整动作库职责；按需读取避免为旧快照执行批量回填。读取并发限制为 2。

新增独立 agent_run 与 plan_draft，不放宽 P2 的单备份单投影任务唯一约束。自动重试未知模型请求可能重复计费，因此 RUNNING 逾期终止为 MODEL_OUTCOME_UNKNOWN；不自动重新调用模型。PENDING 可跨重启领取。代号与截止时间控制最终提交，草案写入与任务成功同事务。

用户确认采用版本条件更新，重复确认返回相同模板 payload。本地事务只添加稳定 ID 的缺失模板，保留已应用后的编辑；动作不存在则整批拒绝。严格校验后调用已有 normalizeTemplate，复用原模板消费边界，不修改既有 Dexie schema、备份格式或历史。

## 代价与边界

- 当前为单实例全局单并发 Agent，不能宣传分布式全局并发限制；多副本部署需额外全局准入设计。
- 按需读取动作库仍会读取最多 20 MiB 原字节；后续负载证明有必要再扩充完整动作库投影。
- 不维护聊天历史，不处理自由文本目标、伤病或器械约束；当前约束是动作集合、天数、时长及明确比较日期。
- Token 仅累计收到完整响应的服务商 reported usage；连接失败但服务商已计费时，客户端无法准确知道费用，不能声称该字段就是账单。
- 此次 deepseek-v4-flash 是用户选定的 API 标识。[官方文档](https://api-docs.deepseek.com/quick_start/pricing/)表明该别名当前由 V4.1 Flash 提供服务；模型权重并未冻结。
- 两个真实合成案例不等于完整约 30 案例 Agent 评测，也不代表训练建议的专业有效性已被验证。
