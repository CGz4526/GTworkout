# 演示与简历证据

适用范围：本机 Docker 演示版。全量验收状态以 [进度](progress.md) 为准；固定 Agent 评测已补，浏览器交互与建议质量仍有待办。

## 五到八分钟演示

1. 打开 localhost:8088，展示本地训练、模板、历史入口，解释断网仍可记录。先保留自己的 JSON 导出，演示时不要清库或用测试文件覆盖已有记录。
2. 云服务登录自己的账号，选择一份合成或自己允许展示的 JSON。说明账号/时区确认、幂等上传和原始备份保留；文件不会自动导入本地。
3. 查看任务进度及 READY 快照，展示覆盖日期、训练天数/次数、有效组、容量与动作趋势；对照原备份日期解释固定快照。
4. 教练计划中选择复盘期间、允许动作、训练天数和时长。只有明确允许付费并确认数据范围后才生成。首批 10 次已用完，本轮新增预算 29/30 次已用，剩余 1 次保留；演示优先展示已有草案和评测报告，不擅自追加请求。
5. 展示草案规则、服务器依据数字和时长估算；由用户确认添加到本地模板。重复应用不覆盖已有编辑，缺动作则整批拒绝。
6. 用报告展示并发幂等、进程中断恢复、冷恢复及后端 P3→P2→P3 兼容演练，不在真实数据上现场强杀或回退。

## 面试时说明的取舍

- 为什么原始文件与投影分开：原文件用于准确恢复，投影用于查询；某次投影失败不丢备份。
- 为什么不用内存异步：任务和状态需要跨进程保存；领取、租约和失效代号解决领取冲突与迟到提交。
- 为什么模型不能直接写库：模型输出不稳定，用户身份/动作权限/数值范围/确认版本需要确定性约束。
- 为什么不自动重试所有模型请求：网络中断时不能确定服务商是否已完成并计费；采用明确失败和用户新任务。
- 为什么先保留单实例：当前目标是有边界、可验证的完整流程，多副本全局准入是后续独立设计。

## 可据实使用的简历表述

按投递岗位选择 3–4 条，并准备对应代码和报告，避免把未来设计写成完成成果。

- 基于 Java 17、Spring Boot、MyBatis 与 PostgreSQL 实现用户隔离的版本化训练备份，采用用户作用域幂等键、请求指纹、事务与配额控制，保留原始文件字节并构建训练分析投影。
- 实现 PostgreSQL 持久任务队列，通过 SKIP LOCKED、租约、执行代号和原子发布处理并发领取及进程中断，使用真实 PostgreSQL 和独立进程故障测试验证恢复。
- 接入 DeepSeek 教练任务，约束只读工具的用户/快照范围，增加动作白名单、计划数值/时长校验、有界调用与版本确认；浏览器事务幂等添加模板并保留用户编辑。
- 使用 Docker Compose 完成本机交付，建立自动化验证、数据库冷恢复与后端版本兼容演练，并保存合成负载与查询计划证据。

性能数字必须附环境、数据量与测试方法。当前短时单用户统计采样不能表述为生产容量、分布式能力、长期稳定性或优化提升；未实现的 RAG、多轮记忆、自动同步不能写入简历。

## 用户验收待办

下列属于尚未由自动化结果替代的人工验收：

- [ ] 桌面/手机下云页面、日期输入、长动作名、任务状态和草案列表正常可读。
- [ ] 相同输入重试提交不重复创建任务；刷新后通过编号重新获取。
- [ ] 确认并应用后模板可正常开始训练，重复应用保留模板编辑。
- [ ] 切换账号、退出登录、401 和网络中断后不显示旧账号结果。
- [ ] 无网络时原本地训练流程可用，云/模型错误不会影响本地保存。
