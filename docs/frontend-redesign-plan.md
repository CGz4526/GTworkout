# Workout前端重设计方案

日期：2026-10-17。状态：用户已明确授权实施，正式React核心页面首批已落地，详见[实施简报](delivery/2026-10-17-14-core-ui-implementation.md)。下方保留设计演进；原型不代表正式页面的当前状态。

## 最新训练录入修订（2026-10-17）

新展开的力量动作缺省1个前置热身组，模板显式设置0仍可不热身。进行中的训练不自动补写，使用“+ 热身组”添加、行下按钮移除；新增工作组独立操作，热身始终插在工作组前。标记切换后也保持热身在前，已有组ID和数据保留。

同动作选定重量后，向后填充未完成、未填重量的组；遇已有重量不覆盖，并作为后面空白组的新继承值。清空只影响当前组，0也是有效重量。新增组继承前面的最近已填重量，新增首个热身不倒用后方的工作组重量。

按动作名识别杠铃/哑铃/深蹲/硬拉/卧推/壶铃等，重量默认键盘，可输入小数及回车确认；明确的史密斯/器械/绳索等名称保持滚轮。模式可手动切换，次数、RPE、休息默认模式不变。不新增器械分类字段或修改schema。

交付与验证见[第16批简报](delivery/2026-10-17-16-workout-entry.md)，本节覆盖下方热身缺省0的旧设计。

## 最新实现修订：个人预设与训练预览（2026-10-17）

按用户最新反馈，本节覆盖下方“六部位直接开练”的旧方案：

- 首页仅保留“预设模板”，使用原“我的模板”的实际内容，不再生成或展示六部位演示卡。旧quick-preset实验模板不删除，仍可在管理页查看。
- 点击卡片进入模板预览，支持移除动作、工作组/次数步进、热身组设置、休息与排序；点击独立开始按钮后才创建训练。工作组最少1，移除整项用“移除”按钮，热身可为0。
- 模板编辑采用串行写入，显示保存中/已保存/失败并可重试；未完成写入时保护刷新。页脚在手机导航上方、桌面内容区底部，控件至少44px。
- 用户明确要求统一现有模板工作组为1，提供显式配置操作；当前5197站点8个模板已执行一次。此操作只更新模板，不调整历史或进行中训练，也不在每次打开页面重置用户后续编辑。
- 可选warmupSets保留在现有模板JSON条目，0–10、旧条目缺省0；展开训练时热身在前，沿用warmup标记及有效组规则。无Dexie schema或备份版本变更，原sanitizeItem不变。
- 趋势顶部先显示训练概览月历，有氧日期使用更大的左上角标、青绿浅底和边框，同日力量与有氧仍可共存。
- 动作库整体重做为搜索、部位筛选、统一动作列表及详情编辑面板，复用原动作、分类与排序数据；桌面左侧分类，手机换行分类，不复用旧页面布局。

验证及范围见[第15批说明](delivery/2026-10-17-15-template-preview-library.md)。

## 精简定稿（2026-10-17，优先于下文）

用户要求去除冗余选框、避免页面繁杂。本节覆盖此前的入口密度及默认展示方案；原功能保留在次级入口，不因此删除数据或撤掉能力。

| 页面 | 默认展示 | 收起或移至次级入口 |
|---|---|---|
| 导航 | 训练、趋势、历史、我的四项 | 教练移至我的，保留清楚的文字入口；动作库从训练页进入 |
| 训练首页 | 开始/继续训练、今日体重、六部位模板 | 不重复展示本周统计与最近训练列表；补录从历史进入，有氧在开始训练后的选择面板内选择 |
| 模板 | 名称、动作数；点卡片直接开始 | 每卡不再并列开始/编辑两个按钮，编辑统一从“管理模板”进入；首次开始前用简短说明告知卡片行为 |
| 正在训练 | 当前动作、组表、加组、添加动作、结束入口 | 不常驻动作筛选/排序/配置框，点击“动作列表”或动作菜单时展开；重量/次数/RPE保持可见 |
| 趋势 | 一组7天/30天/90天切换、频率柱图、月历、体重曲线 | 无第二组体重时间筛选；容量、部位等放“更多分析”；首版不增加均线开关 |
| 历史 | 按日期分组的记录、补录入口 | 默认无搜索框和多组下拉框；单个“筛选”入口按需展开日期/类型，生效后显示摘要与清除按钮 |
| 体重录入 | 默认今天、体重kg、保存 | 日期只显示为可点文字，需要补记时才打开日期选择；不增加目标体重、测量时段或备注选项 |

数据来源不在各页重复提供下拉框：我的页负责明确切换，业务页只显示当前来源文字。由于现阶段训练/趋势/体重的数据覆盖不同，来源必须按实际模块标明；尚无账号全量实时统计时，明确标注“本机统计”，不能沿用全局账号标签制造误解。

每个区域只保留一个突出主动作；更多操作统一到有文字说明的菜单，不堆图标。不把普通单选做成复选框；复选框只用于批量添加动作等确实需要多选的任务。按部位筛选仅在动作选择面板中出现，选定后关闭面板，不占训练页面。

正常保存无需用户反复勾选确认；保留真实数据发送同意、导入覆盖、删除含数据记录等必要确认。错误与未同步提示仍清楚显示。动效仅保留勾选反馈、面板开合与轻量状态过渡，取消装饰性进场、重复数字跳动和图表重播。

本次仅收敛设计，不更改正式React或旧原型。7/30/90天统计口径仍为待确认的独立调整，未因精简方案而实施。

## 最新收敛：以实际使用为核心（2026-10-17）

本节根据用户最新要求收敛此前方案；冲突时以本节为准。交付的是正式前端的实施规格，不另起一套模拟业务。现有原型仅供视觉参考，不能作为本节已实现的证据。

### 页面优先级与导航

日常任务按“开始/继续训练、记今日体重、看训练频率、查某次训练”排序。手机底部为**训练、趋势、历史、教练、我的**，将原“记录”改名“趋势”，避免与历史及记录训练混淆。动作库与模板从训练页进入；教练保留一级入口但不占训练首屏。桌面侧栏固定，趋势/历史内容最大宽度1120px；训练输入列保持640–720px以内，不把组输入横向拉满屏幕。

### 训练首页：每天打开就能操作

从上至下布局如下，手机不设置大幅装饰海报，不把累计成绩放在操作之前：

1. 日期与页面标题；右侧小型数据空间入口，异常同步状态在其下显示。
2. 训练主操作：有进行中训练时显示训练名、已用时间、已完成组和“继续训练”；否则显示“开始自由训练”。有氧和补录使用次级按钮。
3. 今日体重紧凑面板：未记录时显示“今天还没记录”和“记体重”；已记录时显示数值、kg与“修改”。最近一次记录显示明确日期，不能冒充今日值。点击面板可查看体重趋势。
4. 胸、肩、背、臂、腿、核心六个模板，手机两列；卡片显示名称、动作数与计划组数，分别提供“开始”和“编辑”。模板列表不展示所有动作，占用过长时进入详情查看。
5. 本周七天节奏条及力量/有氧次数，入口指向趋势；最近三条训练指向历史。它们属于回顾，不挤占开练区域。

模板直接开始读取保存后的最新版本；有未结束训练时优先恢复并说明，不另建第二次训练。保留用户原模板，通过明确的添加预设操作补齐六类，不自动覆盖、复活或重命名用户资料。

### 训练中：围绕当前组组织页面

顶部固定简洁训练条：返回、训练名、计时和保存状态；结束训练为有文字的次级操作。返回保留训练，与结束操作分开。下方固定紧凑动作目录，显示动作名和完成进度；动作多时使用“动作列表”面板选择，不依赖横滑找到末尾动作。

当前动作展开组表；其他动作折叠为可点开的摘要，切换不丢输入。每组手机布局：第一行组号、热身标识及上次重量/次数参考；第二行重量kg、次数、RPE与完成按钮。RPE始终可见、允许留空。保留原滚轮和键盘输入，切换动作不主动弹出键盘。数字用等宽字形，小数输入允许正常输入过程，不在每敲一个字符时强行格式化。

动作标题右侧提供明确菜单：修改当前训练中的动作设置、替换动作、移除动作。替换只影响当前训练，不静默改动作库或模板；存在已完成组时解释处理范围并确认。新增动作使用底部选择面板：搜索框、可换行部位筛选、已选数量、固定“添加N个动作”按钮，允许连续选多个动作。单组的移除入口放在组菜单，不与完成按钮相邻；含已记录数据时确认，未填写空组可直接移除。

“增加一组”紧接当前动作最后一组；“添加动作”位于动作区末尾，保持易触达。保留动作备注、上次成绩、热身/工作组、默认休息和排序能力；历史已完成账号训练仍遵循当前只读边界。

休息倒计时使用底部紧凑停靠条，显示剩余时间、−30秒、+30秒和跳过；+60秒放展开面板。键盘打开时停靠条收为摘要，不遮住输入和完成按钮。按结束时间计算倒计时，刷新不重置；本次加减不改变默认休息。时间到后变为完成状态，不弹出强制遮罩。提示音/振动沿用已有能力及用户偏好，不依赖新动效实现提醒。

### 趋势：先回答“最近练得规律吗”

固定信息顺序：时间范围与来源 → 力量次数/有氧次数/去重训练天数 → 频率柱状图 → 月历 → 体重趋势 → 容量与部位等次要分析。手机首屏应能看到频率图主体，详细解释收进图表帮助按钮。

频率图使用蓝色力量、青绿色有氧的并列竖柱，纵轴从0开始且为整数；同日多次如实计次，零记录时间段保留。点柱子显示完整起止日期、两类次数，以及“查看该时间段训练”。该操作跳到带日期筛选的历史，返回时保留趋势范围。柱图不能只靠悬停显示数据；提供“数据明细”折叠表供触屏和辅助技术使用。

提供“近7天、近30天、近90天”：本地今天及之前6/29/89天，范围标题显示确切日期。7天按日；30天以范围起点每7天分桶；90天按相交自然月分桶，首末不足整月明确标注。顶部摘要、频率、容量及明细采用同一范围。月历独立选月，标题明确月份；切月份不偷偷改变上方范围。力量填充日期格，有氧使用左上角标，同日可共存；点日期打开当日历史。休息记录不计训练天数。

以上7/30/90是**拟定的统计口径修正**，当前实现的滚动月/不同分桶尚未修改。落地时先记录影响及获得该口径调整确认，再用边界夹具核验；不能将原“近一月/三月”仅改文案为30/90天。

### 体重：每天可记录，也能解释变化

体重不要求当天有训练。首页“记体重”打开轻量面板，日期默认今天、可选择过去日期，输入值与kg同行，明确点击保存；成功后显示“已保存到本机”。失焦不承担唯一保存动作，输入未保存时关闭应提示。已有日期先回填该日值，再保存更新；不因打开面板写入记录。

趋势卡显示最新一次记录的日期与体重、所选范围首末实际记录差值。差值是最后记录减第一记录，标出“较X月X日”，不拿未记录的昨日算变化；增减使用中性色和正负号，不默认减重就是好、增重就是坏。缺少两次记录时显示“再记录一次后可比较”。

折线按真实日期间隔绘制，每次测量显示点；缺失日期留作时间间隔，不能补0或伪造每日测量。单个点可正常显示，无记录显示录入入口；纵轴标明kg且不夸大微小变化。7日均线作为可选叠加，按含当天的7个本地日期内实际测量求均值，至少3个测量日才显示，说明样本数；不替换原始测量线。点图显示日期/实测值，下方可展开测量明细并修改某一天。

记录仍调用`setDayWeight`、同日本机日期唯一，兼容旧`session.weight`回退及weights优先。**当前体重仍是本机数据，不宣称已随账号同步。**账号训练用户也可通过标明“本机体重”的独立面板记录，不能把值归属当前云账号或混入其云统计；跨设备体重单列后续后端能力。

### 历史：可查找、可回看

独立入口始终保留。顶部日期范围筛选与力量/有氧/全部类型筛选；训练名称搜索为补充。列表按本地日期分组，每条突出训练名、部位、时长与有效组；有氧显示类型、时长和有记录时的距离。没有距离不显示0km。点整行查看详情，补录按钮固定在标题区域。

详情首先展示动作和逐组数据，备注/饮食/照片后置；本机编辑保留，账号只读清楚说明。同步状态是小型文字图标，不盖住训练名称。筛选后无数据和首次无历史分别提示；返回保持筛选与滚动位置。删除是独立文字菜单动作，不能滑动一下立即删除含数据的整次训练。

### UI与动效：清楚、克制、可连续操作

沿用冷白、石墨、亮蓝主色，青绿标记有氧和完成；白色表面配细边框，减少多层卡片和大面积渐变。大数字只用在当前组、计时和关键趋势；普通页面正文至少14px、输入至少16px、触控目标至少44px。底部操作遵循iPhone安全区域，弹层内可滚动、底部提交始终可见，关闭后焦点返回触发按钮。

| 交互 | 动效 | 约束 |
|---|---|---|
| 完成组 | 120–160ms颜色与勾选过渡 | 不自动跳走当前行、不抖动庆祝 |
| 新增组/动作 | 160ms透明度与最多4px位移 | 保持已编辑行位置，必要时只滚至新增项 |
| 底部面板 | 180–220ms位移与遮罩过渡 | 输入立即可操作，焦点受控、关闭可恢复 |
| 切换图表范围 | 120ms淡入更新 | 不反复从0生长柱图、不播放曲线绘制 |
| 保存/同步 | 状态文案即时更新、轻量淡入 | 真正成功才显示已保存，错误持续可见 |
| 页面导航 | 默认即时切换 | 不做整页滑动，避免与返回手势争夺 |

减少动态偏好下取消位移、图表动画和非必要过渡。休息数字只更新文本，不持续跳动；训练进行中不展示骨架屏替换已录入的数据。骨架仅限首次读取，空数据用明确文字和入口，不能用合成成绩填充正式页面。

### 正式落地与验收顺序

1. 统一色彩/间距/按钮/面板/导航，明确本机和账号范围；保留旧路由。
2. 改首页与训练输入区，连接原仓储、滚轮、计时和状态保护；不另造模拟记录。
3. 历史独立筛选、频率柱图/月历跳转、今日体重及曲线；统计口径修正单独记录确认。
4. 适配训练库、教练、我的及原52项保留清单；验证深浅色、窄屏、键盘与减少动态。

验收从用户任务出发：从模板开练、加/替换/移除动作、改组重次/RPE、调整休息、刷新恢复并完成；从一根频率柱进入对应历史；不训练也能录体重、同日修改不重复、无昨日数据不制造日变化。工程验证采用类型检查、build/lint及受影响回归，布局须实际浏览器检查；桌面窄屏结果不等同iPhone实测。

## 1. 改造目标

让用户打开就知道今天怎么开始训练，记录时能快速加组、改重量并确认数据保存状态，结束后能找到历史和趋势。账号、备份、教练与原本机功能形成清晰入口；手机保持一只手操作，电脑使用完整宽度。

现版问题：整个网站固定max-w-lg，电脑只剩狭窄列表；首页和账号训练各有一套开始入口；主要依赖同一种卡片和绿色强调，缺少信息层级；教练深藏在云备份后的快照页；本机统计与账号历史的来源不易区分；账号页承担了过多技术说明和操作按钮。

## 2. 推荐视觉：训练日志

按用户反馈改为冷白背景、石墨正文与亮蓝操作色；浅蓝用于轻量选中状态，深色使用蓝黑背景和清晰的浅色正文。去掉原暖白、墨绿与陶橙组合。保留紧凑数据行、训练组表和少量重点面板；教练页面结构保留。品牌仍为Workout／健身记录，不要求重新命名产品。

备选“专注训练”：收起常驻侧栏，以顶栏导航和更直接的训练操作区为主，首页减少统计曝光，把训练开始、当前组和休息操作放前。原型给出两种有布局差异的方向，不把换色当作完整重设计。

| 设计项 | 规范 |
|---|---|

## 3. 信息架构

手机底部五入口：训练、记录、历史、教练、我的。“记录”专注统计趋势；历史记录独立一级模块，不再作为记录页内标签。训练库从首页快捷入口及“我的”进入，仍保留原动作/模板路由与功能。正在训练时隐藏主导航，使用明确的返回与训练操作。电脑侧栏按训练概览、趋势、历史、动作模板、教练和我的排列；备选方向采用顶栏。

顶部持续显示数据空间和状态：账号空间／本机空间。用户须先登录并明确启用账号，不能因新UI自动认领旧历史。正常同步只用紧凑文字；断网、失败、冲突或登录过期时才展开有操作建议的提示。

旧路由继续有效：/、/account-training、/history、/stats、/exercises、/templates、/cloud及既有训练详情路由。可以通过导航归类和页面壳整合，不以删除旧路由制造入口失效。切空间不混合两套记录、不抹掉草稿。

## 4. 页面设计

### 训练首页

标题、日期、空间和同步状态；首屏一个开始/继续训练主动作。自由力量、有氧和补录保持快捷入口；存在未结束训练时优先恢复，不出现第二个新建主按钮。下方提供本周记录节奏和最近记录；在记录未完整拉取时不把缓存统计称为账号全量数据。

每日体重只在本机模式展示；部位模板在首页均可见，并说明本机范围与开始时使用的空间，不冒充账号全量同步。空白用户展示开始训练与复制默认动作库的必要引导，不显示假成绩。

首页新增胸、肩、背、臂、腿、核心六个部位预设（用户列出六类，按六个适配）。模板区位于自由训练/有氧入口之后、最近记录之前，两种数据空间均可看到并标注“本机模板”。每个模板独立提供“直接开始”“编辑模板”；编辑支持改名、动作增删/排序、组次、休息覆盖与恢复默认。直接开始读取最新已保存内容，不进入模板编辑页；已有进行中训练时先恢复，禁止静默另建或覆盖。新增动作重量留空，核心使用次数型动作，不将平板支撑秒数写成次数。

原型初始合成模板自动具备六类；正式实现须保留已有模板及用户修改，以显式初始化/添加处理重名及缺失，不因打开首页反复播种，也不在用户删除后自动重建。模板仍为本机资料，沿用现有模板开始训练的空间边界；不宣称模板已同步账号。

### 正在训练

顶部训练名、计时、保存状态；动作名和上次记录参考；每组明确展示重量kg、次数、RPE、热身/工作组及完成状态。RPE沿用6–10、0.5步进、可空和清空；完成后的输入锁定，取消完成后可编辑。手机每组分两行，RPE始终可见，不靠横滑寻找。保留新增/删除组、动作切换、添加动作、备注和结束训练。

完成工作组后按该动作的默认休息开始倒计时，热身组完成不触发。休息区提供−30秒、+30秒、+60秒及跳过；减到0结束本次休息，不出现负数。调整本次倒计时不改变动作默认值；动作默认休息可单独选择30–600秒、15秒一档，缺省150秒。倒计时按结束时间计算，页面重绘不重启。原型只在当前页面内演示，不宣称支持后台提醒或真实持久化。结束前给出有效组、容量及待同步状态。

输入保持原NumberWheel/stepper可用性，键盘弹起时不挡当前行；横滑不是删除/编辑的唯一入口。未完成训练返回首页应保留，取消短训练保留既有状态规则；原设备限制与多标签编辑保护必须可理解。

### 记录与详情

按本地日期分组，区分力量、有氧、休息；每条展示名称、时间/时长、对应摘要及同步状态。账号已完成记录维持首版只读，不画成可直接改删。详情先展示训练内容和组，再放备注及兼容附件，操作不与状态挤在同一行。

### 趋势

训练频率改为按时间排列的竖向分组柱状图，力量/有氧同图比较，纵轴整数次数、横轴日期/时间段，零记录日期保留位置，不使用进度条冒充频率图。容量也使用竖向柱图；按部位次数可保留横向分布展示。近一周按日、近一月按7日时间段、近三月按自然月聚合；范围摘要、柱值及下方明细来自同一集合，月历月份仍独立。标明首末日期及末段未完整的时间边界；图下可选时间段查看实际合成训练明细并直达详情。原型对齐后的近三月为8月1日至10月17日，正式统计口径调整须单独记录和验证。

先选数据来源，再选时间范围。现阶段明确区分“本机记录”和“云端快照”，不默认用本机统计冒充账号全量实时统计。云快照展示数据截止日和快照选择；容量单位kg·次，完成非热身组语义沿用src/lib/set.ts。没有数据时解释原因，不显示虚构增长、恢复评分、卡路里或1RM。

保留原统计页“训练概览”月历，作为频率柱图之后的独立区域。周一为每周起点，支持上月/下月/回到本月；按本地日期显示力量、有氧及同日两者标记，用文字/形状配合颜色。休息记录不算训练日；同日多次训练在月历中去重，但“训练次数”图继续按原记录次数口径。月历显示力量天数、有氧天数与去重训练天数，两类天数不能直接相加冒充总天数。数据源维持本机记录，账号全量实时月历须待相应统计能力落地，不能借前端改版虚构已有能力。原型仅用明确日期的合成数据，切到无记录月份展示空月。

### 动作与模板

一个训练库入口，内部切动作/模板，动作支持“全部、肩、胸、背、腿、二头、三头、核心”部位筛选，与名称搜索组合使用；添加动作时同样可按部位选择。部位标签换行展示，手机不隐藏在横滑列表末端。动作详情保留名称、身体部位、默认休息和描述要点的编辑入口；默认组数属于模板条目，不误标为动作字段。模板清楚标记本机范围；账号动作库复制有明确来源和结果，不因设计整合自动复制或上传。

### 功能保留检查

完整源码对照见[功能对照清单](frontend-feature-parity.md)，逐项列出52项功能与适配边界。有氧月历标记改为日期格左上角三角，保留同日力量/有氧叠加及文字说明。趋势补齐近一周/一月/三月、部位次数、力量频次/容量、有氧汇总/类型/频次及每日体重趋势。

正式改造须逐项对照现有页面：动作部位/搜索/增改删/默认休息/描述，模板增改删及条目休息覆盖，逐组重量/次数/RPE/热身/增删/完成，训练备注、休息、恢复与结束，力量/有氧补录与休息日、体重/照片、历史详情、统计、导入导出、账号及教练。原型优先演示关键交互，不以原型未展开为由删除原功能。当前修订补齐部位、逐组RPE及休息调整；其余正式复用流程仍按落地批次实施。

### AI教练

把入口从备份深层操作中提升为一级导航，但保留真实依赖：登录→选择READY快照→日期与允许动作→训练天数/时长→数据发送同意→提交任务→查看草案→确认并应用本机模板。显示“快照数据”及截止日期，不宣称模型已读取最新账号训练。

表单、生成进度与草案审阅分阶段，任务刷新恢复保留；生成费用和发送范围在操作前明确，失败不自动重放付费调用。模型未配置、无快照/无动作库、过期登录、规则拒绝、已确认未应用都要有专用状态。原型只本地展开合成草案，不发送模型请求。

### 我的与账号/数据

账号与登录、空间切换、主题、数据导入导出、云备份、旧训练迁移和隐私集中呈现。用简洁的数据范围清单说明训练已同步、模板/体重/照片仍本机；导入继续先预览再确认，不能用“立即同步全部”掩盖实际能力。

## 6. 落地分批

1. 本批：设计规范、页面/状态结构、两种交互原型；不替换src、不改库、不部署。
2. 用户确认后：先落地设计令牌、公共页面壳、响应式导航、表单/按钮/状态组件，再改首页/账号页。先统一导航和数据空间，再处理视觉细节，避免另造一套训练实现。
3. 训练中/补录/详情：复用既有仓储、同步器、输入验证和计时，逐页替换表现层；不在UI组件新增独立写库逻辑。
4. 历史/趋势/训练库、快照教练和我的页，保留接口和旧路由。需要新增后端能力的设计另列后续需求，不靠静态假值填满界面。
5. 实际浏览器与iPhone验收后，构建新镜像版本。已暂存的服务器发布包仍是旧UI版本，不能把原型当作已部署版本；正式发布另行授权。
