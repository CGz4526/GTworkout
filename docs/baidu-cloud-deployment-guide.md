# 百度智能云首次部署指导

日期：2026-10-17。目标：2核4GB单机部署Workout账号训练首版，供个人手机长期使用。

状态：部署前指导；尚未连接云服务器、安装软件、迁移目标库或公开发布。实际系统镜像、产品类型、地域及域名待确认。本文不是已完成生产部署的记录。

后续实际进展（2026-10-17）：已核对北京区域Ubuntu 24.04 amd64，专用SSH连接成功；Docker Engine 29.9.1与Compose 5.6.0已安装，服务与离线传输后的官方测试容器运行通过。上方状态及下文初始检查步骤保留为首次准备记录；当前待确认域名/备案，尚未执行项目建库迁移或正式部署。云主机直接访问Docker Hub超时，见[安装交付](delivery/2026-10-17-06-baidu-docker-installation.md)。

## 一、先查看实例信息

登录百度智能云控制台，打开购买的实例。产品可能是“轻量应用服务器LS”或“云服务器BCC”，不要根据套餐名称猜测。

记录产品类型、地域、系统镜像名称、CPU架构、公网IPv4和系统盘大小。公网IP与登录用户名可以提供给协作者；密码、SSH私钥、控制台访问密钥不要发送到聊天。

若购买时选了WordPress、宝塔或其他应用镜像，先报告实际系统，不自行重装。重装会影响磁盘数据，需要另行确认。

## 二、先登录并只读检查

优先使用实例详情的“远程登录”或VNC入口。操作位置随产品和控制台版本可能变化，见[百度LS登录说明](https://cloud.baidu.com/doc/LS/s/3l82plvzt)。忘记凭据时由用户在云平台完成设置；不要把新密码交给协作者。

在远程Linux终端分别执行：

```bash
cat /etc/os-release
uname -m
whoami
free -h
df -h /
docker --version
docker compose version
```

最后两条出现“command not found”仅表示尚未安装，不用自行执行来源不明的一键安装脚本。分享这些输出即可判断后续命令；不要发送完整环境变量、docker inspect或Compose展开配置。

需要从Windows连接时，在本机PowerShell输入`ssh 登录用户名@服务器公网IP`。用户名以实例说明为准，不假设一定是root或ubuntu。首次连接应核对主机指纹；密码输入不显示字符属于正常现象。若超时，先核对实例运行状态、公网IP及SSH规则；若提示Permission denied，核对用户名和认证方式，不重复重置系统。

## 三、网络规则

LS使用“防火墙”；BCC通常使用“安全组”。先查看已有规则，保留控制台的恢复入口。SSH需要TCP22，建议来源限制为自己当前公网IPv4/32；动态网络地址变化时再更新。使用云平台VNC时不为解决VNC访问问题盲目向全网开放SSH。

正式HTTPS部署准备好后再配置TCP80和TCP443面向公网。PostgreSQL5432、Java8080和本机入口8088均不对公网开放；应用和数据库仅在Docker内部通信。不要通过关闭全部防火墙解决连接问题。

## 四、准备长期域名

如果已有域名，提供域名和备案状态即可；没有域名，可购买一个普通域名并完成实名，后续使用例如`workout.example.com`的子域名。域名可以在其他服务商购买，不要求与服务器同一家。

若服务器在中国大陆，按百度接入要求办理备案，域名实名主体等资料以官方备案流程为准，见[百度域名备案问题](https://intl.cloud.baidu.com/zh/doc/BCD/s/Dk2ylkl48-intl)。备案可与镜像、配置准备并行。

DNS解析规划：子域名`workout`，记录类型A，记录值为服务器公网IPv4。备案与接入条件符合后再按上线步骤生效。域名必须与HTTPS证书匹配，不能用普通HTTP公网IP的访问结果代替iPhone PWA离线验收。

## 五、部署工程待完成内容

以下属于下一批工程清单，不能当作当前仓库已有的可执行命令。

1. 按实际Linux版本准备Docker Engine与Compose。Ubuntu使用[Docker官方安装说明](https://docs.docker.com/engine/install/ubuntu/)；不安装Docker Desktop，不额外安装宿主机Java、Node或PostgreSQL。安装软件及修改系统配置前，按AGENTS.md取得对应授权。
2. 从已验收源码重新构建server/web镜像，使用新版本标签和摘要。尽量在本机构建后传输，降低云主机CPU、内存和国内基础镜像下载压力；旧p3镜像标签不代表包含训练首版代码。
3. 准备Linux长期部署配置：独立Compose项目、持久PostgreSQL卷、容器资源限制、日志轮转、重启策略、HTTPS入口和证书续期。现有infra/start-local.ps1是Windows本机脚本；infra/compose.yaml默认只绑定127.0.0.1:8088，不能照抄后期待公网访问。
4. 审阅并版本化新服务器数据库迁移：现有Flyway V1–V4加账号训练所需五张新增表。目前docs/contracts/r2-training-schema.sql只获准用于隔离库，不能直接挪入生产执行。正式迁移须单独批准，不修改已应用迁移。
5. 仅在目标新库就绪后启用WORKOUT_TRAINING_WRITE_ENABLED。HTTPS启用WORKOUT_COOKIE_SECURE并核对代理转发信息。数据库密码通过隐藏输入及运行时注入，不写源码、真实.env、命令历史或日志。
6. 先限制访问建立个人账号，再关闭公开注册；确认身份隔离及完整训练保存。DeepSeek接入可后置，不影响记录训练；不复用聊天中暴露的密钥，不在验收时擅自创建付费任务。
7. 经对应授权启动正式服务。网页检查、训练写入、刷新、PWA安装、离线补传、容器重启后数据保留均需实际确认。健康状态不能替代业务验收。
8. 建立定期数据库备份与服务器之外的受保护副本，验证一次隔离恢复。备份可能含账号、会话和训练记录，不放入公开静态目录或源码包。

## 六、原训练记录如何接入

临时手机测试库已经结束，不作为正式数据源。正式账号创建后先做合成训练验收。原来PWA中的真实训练先通过原应用导出并保留独立副本，再使用新站点明确的云备份上传、预览和确认导入流程。换域名后浏览器不会自动共享原站IndexedDB。

首版导入已完成训练，不等于模板、体重、照片及附件全部跨设备同步；这些边界仍见[首版交接](training-v1-handoff.md)。不要直接复制浏览器profile、覆盖原库或把旧备份当作数据库恢复文件。
