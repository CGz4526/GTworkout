# gtworkout.space 上线清单

更新：2026-10-19。本文为现有单机部署方案的域名落地清单，不是生产执行授权。

## 固定入口

- 正式地址：`https://workout.gtworkout.space`。
- DNS：腾讯云 DNSPod，`workout` / A / 默认 / `120.48.174.63` / TTL 600。用户已提供成功解析结果；本批不修改DNS。
- 服务器：百度云北京 Ubuntu 24.04，2核4G；ICP备案由用户进行中。
- 不新增根域名、www、api或泛解析；API与页面同源，路径为 `/api/`。

## 备案期间可执行

- 本机构建、版本化导出并上传镜像；保留旧包，不覆盖用户数据。
- 在独立合成环境核验Compose、HTTPS路由、静态缓存和启动授权保护。
- 审阅训练库迁移、证书签发/续期、数据库凭据保存、备份恢复与更新流程。
- 不启动正式数据库，不公开80/443，不配置真实模型调用。

## 正式数据库待批准项

目标仅为新服务器的 `workout-prod` 专用库；不使用本机运行库或浏览器历史初始化。
既有Flyway V1–V4保持不变。基于 `docs/contracts/r2-training-schema.sql` 的五表
`live_exercise`、`live_session`、`live_session_exercise`、`live_set`、`training_mutation`
已作为 `V5__create_live_training.sql` 纳入正式迁移，完整Wrapper verify通过（87项单元、33项集成，0失败/跳过）。覆盖空库自动迁移、V4升级保留账号、重复迁移无新增执行及训练HTTP；服务器执行未获批准，不能直接开启训练写入或启动含V5的后端。

正式执行前仍需单独批准服务器迁移范围。本轮编写V5并在独立PostgreSQL验证，生成新的暂存发布包；Flyway启动会自动应用V5，与训练写开关无关。
当前暂存包用于部署准备；真实域名TLS、正式账号、正式数据库执行及手机验收完成前，不能称为已交付的线上训练服务。既有恢复集成用例通过不等于含真实训练内容的V5全量恢复演练已完成。

## HTTPS与账号待完成

- 证书须覆盖 `workout.gtworkout.space`，完整链和私钥分别为服务器 `/opt/workout/tls/fullchain.pem`、`privkey.pem`；不使用合成证书。
- 推荐DNS验证；TXT值以签发工具实际结果为准。不在文档中存放DNS令牌或私钥。
- 证书安装、凭据保护及续期系统配置需另行批准；当前尚未自动续期。
- 先限制访问建立个人账号，再关闭注册，验收Secure Cookie与跨账号隔离。
- 取得真实备案号后添加网站页脚及工信部查询链接，不编造号码。

## 正式发布与验收

- 备案通过，数据库与证书验收完成，再批准正式公开启动及80/443规则。
- Java与PostgreSQL不开放宿主端口；SSH来源限制须兼顾现有管理连接。
- iPhone真实域名验收：登录、模板开始、热身/工作组、保存刷新、断网补传、历史、体重、添加主屏幕与版本更新。
- 新域名不会自动拥有旧origin的IndexedDB；先留存旧JSON，导入须明确操作，不能覆盖或清空旧数据。
- 模板、体重和照片仍有本地存储边界，参照 `training-v1-handoff.md`，不宣称全部跨设备同步。

## 运维

- 上线前落实每日备份、服务器外受保护副本与隔离恢复演练；当前只有手动备份脚本。
- 更新顺序：本机验证构建、上传校验、备份、审阅迁移兼容性、替换镜像、手机验收。
- 不执行 `docker compose down -v`，不通过删卷或换密码处理升级故障。
- 旧镜像保留不等于回退已经验证；数据库有变化时单独核对兼容性。
