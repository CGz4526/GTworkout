## 本轮完成范围

准备Linux Compose、单层Nginx HTTPS模板、启动/证书检查/手动备份脚本、可校验的镜像发布包；允许暂存到新服务器，不创建项目数据库或启动生产容器。仅用本机自有临时容器及合成TLS夹具验证配置，不使用真实训练、账号或模型。保留现有本机8088与其数据库。

## 运行设计

发布项目名固定workout-prod，三服务为web/server/db。只在web发布端口；默认绑定127.0.0.1:8088及8443，公开前必须明确选择公网80/443并获批。web直接终止TLS并代理API，避免多层代理错误传递HTTPS信息。服务端固定Secure Cookie，训练写入口默认关闭、公开注册默认关闭，真实模型默认空。

web/server/db内存上限规划为128MiB/768MiB/512MiB，server沿用镜像内JVM比例参数。数据库连接池设置上限5；PG shared_buffers=128MB、max_connections=30。日志每服务限制为10MB×3，数据卷独立持久化；这些是起始配置，不是容量承诺。

镜像在本机构建并导出，在服务器校验文件摘要和镜像ID后导入，后续启动使用pull_policy=never。不能依赖服务器当前无法直连的Docker Hub，也不配置来历不明的镜像站。现有已验收基础镜像摘要保持不变；生产发布前还需审阅其安全更新，未执行漏洞扫描，不宣称基础镜像没有漏洞。

配置以WORKOUT_DOMAIN注入实际域名，证书及私钥仅从服务器专用TLS目录只读挂载，不进入源码、镜像或发布包。当前域名实名等待同步，尚无备案号，包中不编造域名和备案号。证书签发/安装、首页备案号链接及续期方式在实际域名、备案就绪后落实；本轮只提供证书有效期核验与热重载脚本，不宣称自动续期或定时备份已配置。

## 凭据与操作边界

启动脚本仅接受运行时注入的数据库密码，不生成真实.env，不打印展开Compose或容器Env。重启已有容器不需要重新输入，重建/升级仍需同一数据库凭据；正式注入前确认保存与恢复方式。模型密钥后置单独配置，不使用旧聊天密钥、不新增付费请求。

备份脚本只读导出本项目标签唯一数据库，生成umask077保护的custom归档及SHA256，不覆盖已有归档，不自动清理。归档检查只证明可列出结构，不等于恢复通过；新五表冷恢复、异地副本及定期执行仍是正式上线前检查项。定时器/系统配置不在本轮执行范围。
